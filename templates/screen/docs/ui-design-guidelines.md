# 大屏 UI 设计规范

本规范适用于 Naive UI 大屏工程。页面以信息展示和远距离阅读为主，使用统一深色主题与设计画布。

## 画布与布局

- 默认设计尺寸为 1920×1080，尺寸配置集中在 App.vue 的 ScaleLayout 上。
- fit="fill" 分别缩放宽高以铺满窗口；fit="contain" 等比缩放并居中，允许留边。以产品实际展示环境选择，不在页面内重复缩放。
- 页面使用设计坐标下的 px，主结构优先 Grid、局部排列用 Flex，布局、间距和尺寸优先 UnoCSS；动态缩放和复杂选择器使用 Less。
- 根页面占满设计画布。列和面板使用 min-w-0、min-h-0；长标题截断，说明文本明确换行或行数上限。
- 超出面板的数据在面板内滚动，不依赖 body 滚动，不用 overflow-hidden 掩盖布局错误。
- 字号、图表、弹窗与下拉菜单都需检查缩放后的可读性和定位；不套用 PC 最小窗口宽度要求。

## 主题与排版

- 使用 Naive UI 的 darkTheme 和入口 themeOverrides。主色统一使用 UnoCSS primary、Less @primary 与匹配的组件主题色。
- 背景、面板、正文、弱文本通过项目主题变量统一维护，默认背景 #061127，正文 #d1ecff。
- 允许深色背景、低强度渐变与细边框。装饰不得遮挡关键数据或降低对比度，避免无业务意义的大面积发光和持续闪烁。
- 设计画布下推荐页面标题 32–40px、区块标题 20–24px、正文 16–20px、关键指标 36–56px；远距离显示以实际屏幕验证为准。
- 间距遵循 4px 节奏，同级面板保持一致。数字优先使用等宽数字，单位与主数值区分层级。
- 状态色应表达明确语义，颜色不能成为区分状态的唯一方式。

## 组件与浮层

- 按钮、选择器、表格、弹窗、抽屉、消息等直接使用 Naive UI，不重新实现基础组件，不引入另一套 UI 框架。
- 模板中的 n- 前缀组件由 NaiveUiResolver 解析；useMessage、useDialog、主题、语言和类型显式导入。
- useMessage、useDialog 必须在相应 Provider 的后代组件内使用。非组件代码可在入口初始化后使用 window.$message、window.$dialog。
- 入口的消息和对话框 Provider 挂载到 #app，与画布使用同一缩放坐标系。新增 Select、Dropdown、Popover、Drawer 时按组件实际 to 属性明确挂载点，并检查点击点、定位、遮挡和边界。
- 不再为浮层乘一次缩放比例，不使用无限增大的 z-index 修补定位问题。
- 危险操作使用对话框确认，失败信息说明原因和下一步。

## 数据展示与图表

- 图表统一复用 src/components/EchartsCom.vue，图表容器必须有确定尺寸。
- 指标必须有名称、单位、时间范围和统计口径；图表标题、图例和坐标文字在深色背景上清晰可读。
- 模拟数据明确标注为示例，不将模板占位值呈现为真实业务数据。默认首页只展示技术接入示例。
- 加载、空数据、接口失败、部分数据缺失应有各自状态；不把无数据当作零值。
- 动画只用于必要反馈和数据变化，减少持续动效，避免频繁全量重建图表。

## 完成后检查

- 设计尺寸和至少一个不同宽高比窗口中检查 fill、contain 的预期表现。
- 标题、长中文、英文和数字串不撑开面板，图表及标签不裁切。
- 消息、弹窗和下拉浮层定位正确，能正常点击、关闭，不重复缩放。
- 主题一致、文本对比清晰，没有无来源业务指标或无意义装饰。
- 浏览器运行时检查须经用户确认，结果说明页面、操作、Console、Network、布局与浮层。
