# 工程模板 project-templates

## 功能概述

脚手架提供 PC 和大屏两类工程模板。创建时根据工程类型，将公共基础与对应类型的文件组装为一个可独立开发的 Vue/Vite 工程。生成后的工程只包含所选类型的 UI 框架、入口、组件和开发规范。

## 需求规则

### 工程类型

| 内容 | PC（`pc`） | 大屏（`screen`） |
| --- | --- | --- |
| UI 框架 | Ant Design Vue | Naive UI |
| 页面适配 | 宽度不低于 1440px 的桌面窗口，流式布局 | 默认 1920×1080 设计画布，通过 ScaleLayout 缩放 |
| 默认视觉 | 沿用现有浅色 PC UI 规范 | 深色大屏主题，独立的布局、排版、图表和浮层规范 |
| ScaleLayout | 不生成组件、引用及对应测试 | 保留组件与测试，在 App.vue 根部引用一次 |
| 图表 | 保留 EchartsCom | 保留 EchartsCom |
| 开发规范 | PC 专用 AGENTS.md、UI 规范 | 大屏专用 AGENTS.md、UI 规范 |

两类工程共用 Vue、Vite、TypeScript、Vue Router、Pinia、Axios、VueUse、UnoCSS、Less、图标加载、代码检查和测试工具。公共部分不包含任一 UI 框架的运行时代码或类型依赖。

### 开发规范

- 现有 PC 的 AGENTS.md 和 UI 规范作为 PC 模板规范保留。
- 大屏 AGENTS.md 继承通用编码、需求文档、测试、开发流程和 Git 边界约定；替换其中的 PC 窗口要求和 Ant Design Vue 使用约定。
- 大屏明确使用 Naive UI，模板标签按配置自动解析，组合式 API、函数式 API 和类型显式导入。
- 大屏 UI 规范不继承 PC 的浅色主题、禁止深色及 1440px 最小窗口规则；使用设计画布尺寸与缩放策略描述适配边界。
- 大屏规范明确主题变量、字号层级、布局间距、数据单位与口径、图表复用、空状态、浮层挂载和动效约束。
- 生成后的规范文件路径仍为 AGENTS.md、docs/ui-design-guidelines.md、docs/testing-workflow.md、docs/requirements/README.md，不要求使用者在同一工程中选择阅读两套规范。
- 测试文档、默认视口和示例随工程类型匹配；PC 不引用已移除的 ScaleLayout。
- 脚手架仓库自身的维护规则与生成项目的规则分开，避免用 PC 规则约束大屏模板开发。

### UI 框架隔离

- PC 只声明和接入 Ant Design Vue，大屏只声明和接入 Naive UI。
- 同步区分 package.json、锁文件、组件自动解析器、TypeScript 配置、全局类型、入口主题和中文语言配置。
- 大屏入口配置 Naive UI 的消息和弹窗能力；类型与实际 API 保持一致，不保留指向 Ant Design Vue 的类型声明。
- 首页示例、图标及 README 与所选 UI 库一致。
- 不引入新的业务页面、登录、权限、接口或 Store 业务规则。

### 大屏入口与缩放

- 在 App.vue 根部显式引入并挂载 ScaleLayout，示例采用 1920×1080、fit="fill"。
- 保留现有缩放语义：fill 分别缩放宽高以铺满窗口；contain 等比缩放并居中，允许留边。
- ScaleLayout 作用于整个 body，在应用根部只挂载一次，不在各路由页面重复挂载。
- 组件卸载时清理 resize 监听，并恢复自身修改的全局样式和属性，避免重新挂载或热更新留下污染。
- Naive UI Provider 和浮层挂载方式与整体缩放配套，不额外创建第二套缩放机制。
- 首页仅演示模板已就绪和基础 UI 接入，不生成带虚构业务数据的看板。

### 创建行为

- 创建脚本显式接收工程类型和目标目录，支持 pc、screen；无效或缺失类型应给出明确错误。
- 生成顺序为公共文件、所选模板差异文件、合并所选依赖配置。
- 输出为普通 Vue/Vite 工程，不携带另一个模板、生成器源码或脚手架维护文档。
- 生成后的工程保留 pnpm dev、pnpm check 等开发命令。
- 目标目录不存在时创建；已有空目录可使用；非空目录拒绝覆盖。
- 生成器只负责文件生成，Git 初始化和依赖安装继续由创建工程流程执行。
- 安装后锁文件必须与所选类型依赖一致，不把另一套 UI 框架的锁文件直接用于生成结果。

### forge-starter 技能

- 保持现有类型提问、工程名和路径收集、默认值处理、成功结果输出格式以及安装依赖的交互流程。
- 用户选择“大屏”映射为 screen，选择“PC”映射为 pc。
- 技能仍获取 CDTRSFE/vite-tpl 模板仓库，内部调用仓库提供的生成器，将对应类型输出到用户指定目录。
- 下载脚手架使用独立临时目录；用户工程目录只接收生成结果。
- 技能不再通过事后编辑 App.vue 给同一套工程套上 ScaleLayout；差异由模板自身提供。
- PC 和大屏都沿用初始化 Git、安装依赖、核实结果的既有流程；不自动提交或推送。
- 同步范围是本机 forge-starter 的技能文件；模板远程获取是否可用取决于对应仓库版本是否已包含生成器。远程版本缺失生成器时明确报错，不静默退回混用模板的旧流程。

## 实现方案

### 文件组织

- templates/base/：公共源码、资源、工程配置及可继承的通用文档。
- templates/pc/：PC 专属入口、首页、依赖差异、类型配置及开发规范。
- templates/screen/：大屏专属入口、首页、ScaleLayout 及测试、依赖差异、类型配置及开发规范。
- scripts/create-project.mjs：使用 Node.js 组装模板并校验参数和目标目录。
- scripts/create-project.test.mjs：生成器行为测试。
- 根 README.md：脚手架维护和两类工程的创建方式；生成工程使用对应模板的 README.md。
- docs/requirements/project-templates.md：脚手架模板生成机制，仅保留在脚手架仓库。
- 本机 /Users/puyuchun/.codex/skills/forge-starter/SKILL.md：沿用交互契约，接入按类型生成的流程。

### 数据流

用户明确工程类型、名称和路径 → 获取脚手架 → 按类型组装公共基础与模板差异 → 生成独立工程 → 初始化 Git → 安装所选依赖 → 汇报实际创建结果。

### 关键决策

- 差异在创建阶段确定，生成项目运行时不提供 PC/大屏切换开关。
- 公共基础集中维护，避免复制两套完整工程后造成通用配置漂移。
- 生成结果保留现有单工程开发体验；脚手架仓库承担模板维护和生成职责。
- 模板负责正确的依赖、入口及规范，技能只负责收集信息、选择模板和执行创建流程。
